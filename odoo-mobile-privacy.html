Privacy and data handling

This page describes the privacy model of the current Odoo Mobile Android client.

Overview

Odoo Mobile connects directly to the Odoo server profile configured by the user. Odoo remains the system of record for business data. The app is designed for controlled internal use and does not require a separate business-data cloud owned by Odoo Mobile.

Connection credentials

Odoo API keys and passwords are stored encrypted at rest using AES-GCM with a key held by Android Keystore. Credentials are managed per connection profile and are not intended to be placed in source code, logs, screenshots or analytics.

Local data

The app keeps profile-isolated customer and activity caches, recent records and favourites. Customers are read-only offline; To Do changes and supported job evidence use persistent encrypted retry outboxes. Business caches, search and mutation databases use SQLCipher with an installation key wrapped by Android Keystore. Supported local cache clearing does not delete Odoo records, credentials or pending work.

Network traffic

Normal remote connections require HTTPS. Plain HTTP is restricted to explicit local-development hosts such as localhost, 127.0.0.1 and the Android emulator host address. TLS certificate validation is not disabled.

Device privacy controls

The app includes an optional privacy screen that can block screenshots and the Android recent-app preview. Sensitive areas may also be protected using device authentication according to the user's settings.

Notifications

Activity reminders are opt-in and rely on Android notification permission where required. Reminder refreshes are used only for relevant due or overdue activity information available to the connected profile.

Files and attachments

Odoo activity attachments can be uploaded, listed, downloaded and opened through Android. Supported To Do photos, signatures and documents can queue offline; other business-record file operations require an online connection. Users should avoid uploading sensitive material unless the connected Odoo server and user permissions are appropriate for that data.

Backups and transfer

Profile metadata and encrypted business databases are excluded from Android backup/device-transfer paths, helping reduce unintended propagation of business data between devices.

Third-party services

The app can invoke Android system applications for actions such as email, phone calls, mapped addresses and file opening. Barcode lookup may use Google Play services. Those external applications and services have their own privacy practices.

Important deployment note

The current direct-connector architecture is intended for controlled internal deployment. For broader public distribution, a managed gateway is recommended so authentication, auditing and policy controls can be centralized.
